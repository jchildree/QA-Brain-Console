# Case: EQMS Documentation Drift

## Symptom

The EQMS doc corpus is large and disciplined on its face -- 39 ADRs with a
clean INDEX, 6 numbered requirements docs plus a versioned tech spec, a
39-page LLM wiki with its own suggestion-review pipeline, and a phase
registry with a fixed status lexicon. Every one of those systems has a
built-in mechanism for staying in sync with the decisions that feed it.
This case is about the four places, found by reading the corpus end to
end, where that mechanism ran once and then stopped.

## Thesis

EQMS documentation does not have a coverage problem -- it has a
**closed-loop problem**. Decisions get made and written down correctly the
first time; nothing in the corpus enforces that the *downstream* copies
of that decision (a registry row, a wiki page, an implementation backlog,
a promised guide, a sibling design doc) get updated or reconciled
afterward. Five independent instances of the same failure mode surface
across five unrelated parts of the corpus -- four are lag (a decision
moved on, its downstream copy didn't), one is worse: two accepted
decisions about the same database column that cannot both be true at
once, with nothing in the corpus flagging the clash.

## Argument

**1. The document that calls itself authoritative is the one that's behind.**
`phase-status/INDEX.md` states outright that it is the "single source of
truth for phase status" and that "all other documents defer to this table
on conflict." Its own Phase 01 status narrative stops at ADR-031, while
`docs/adr/` has moved on to ADR-039 and its sibling file in the same
folder, `P0-CRITERIA.md`, already cites the full ADR-001-through-039
range. ^[[[Source Phase Registry ADR Lag]] · verified]

**2. A correct, filed suggestion sat unapplied for 26 days.** The wiki's
own suggestion-review workflow correctly identified, on the day ADR-032
was accepted, that `Business Identifier Numbering.md` would need a
rewrite. That suggestion note is still sitting in the pending queue;
the page it targets still teaches the exact pre-ADR-032 formats the
suggestion says are wrong. The pipeline worked -- the follow-through
didn't. ^[[[Source Business Identifier Numbering Stale Page]] · verified]

**3. A platform-wide rule has never been instantiated even once.** The
root `CLAUDE.md` requires an admin guide and a troubleshooting guide per
app. EQMS's own `CLAUDE.md` names the exact two files it owes and flags
them as not yet written -- and it's right: neither file exists, and
neither does the root-level `docs/` directory the convention assumes.
This isn't EQMS falling behind a rule everyone else follows; the rule has
no working example anywhere in the repo yet. ^[[[Source Docs Owed Never Written]] · verified]

**4. "Decided" and "built" are being read as synonyms.** `EQMS-CRITICAL-ISSUES.md`
is otherwise the most rigorous document in the corpus -- it tags every
item RESOLVED / DECIDED / DEFERRED / OUT OF SCOPE and cites the exact
migration that resolves each one. But of the 6 CRITICAL items tied
directly to the system's 21 CFR Part 11 claim, the file's own closing
backlog section still lists the e-signature payload column, the
audit-log action typing, and the audit FK policy as unbuilt. The
document is honest about this -- the gap is between what QA decided on
2026-06-12 and what the backlog says has actually landed. ^[[[Source Critical Issues Backlog Undone]] · verified]

**5. Two accepted decisions about the same column contradict each other, and nothing
notices.** `EQMS-CRITICAL-ISSUES.md` issue 5 decides to constrain
`audit_log.action` to exactly `'INSERT' | 'UPDATE' | 'DELETE'`. But
`Audit Contracts.md` and `Training Escalation.md` -- both describing
already-accepted, ADR-backed designs -- document `action` values of
`DOCUMENT_FILE_UPLOADED`, `DOCUMENT_PDF_GENERATED`, and `ESCALATION_SENT`.
None of those three fit the proposed CHECK constraint. This isn't lag,
it's a live conflict: implementing issue 5 as decided breaks two other
accepted designs, and no document in the corpus defers to another on it. ^[[[Source Audit Action Column Contradiction]] · verified]
