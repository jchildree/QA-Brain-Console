# Audit Action Column Contradiction

`EQMS-CRITICAL-ISSUES.md` issue 5 (DECIDED, 2026-06-12) proposes:

```
action NVARCHAR(10) NOT NULL CHECK (action IN ('INSERT','UPDATE','DELETE'))
```

with the rationale that the audit log currently has no action discriminator
and needs one so INSERT/UPDATE/DELETE are always distinguishable.

But three other accepted-design wiki pages already document `audit_log.action`
being written with semantic, non-CRUD business-event strings, not CRUD verbs:

- `Audit Contracts.md`: `action = 'DOCUMENT_FILE_UPLOADED'` and
  `action = 'DOCUMENT_PDF_GENERATED'`, written by `document_service.py`
  via `write_field_change()`.
- `Training Escalation.md`: `action = 'ESCALATION_SENT'`, written by
  `training_service.run_escalation()`.

None of `DOCUMENT_FILE_UPLOADED`, `DOCUMENT_PDF_GENERATED`, or
`ESCALATION_SENT` satisfy `CHECK (action IN ('INSERT','UPDATE','DELETE'))`.
If issue 5 is implemented exactly as decided, every one of these three
already-documented write paths starts throwing a CHECK-constraint
violation. This is not a "decision not yet built" gap like the other
findings in this case -- it's two accepted decisions that cannot both be
true of the same column at the same time. Neither document defers to the
other; nothing in the corpus flags the conflict.

Not verified against the live migration/code -- only that the two design
decisions, as written, are mutually exclusive.
